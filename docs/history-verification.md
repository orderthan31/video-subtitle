# 작업 이력 검증

2026-09-11.

## 구현 범위

- `job.json` 최종 상태 스냅샷을 미디어 결과와 별도 기간으로 보관한다. 모든 상태 전환을 저장하는 감사 이벤트 로그는 아니다.
- 결과는 기본 24시간, 이력은 완료/실패/취소 후 기본 90일이다. 결과 기간을 늘려도 한 번 만료된 파일은 복구되지 않는다.
- 기존 완료 시간은 바꾸지 않으며, 반복 정리가 이력 만료를 연장하지 않는다. 결과 정리에 실패하면 다음 GC에서 재시도한다.
- 다운로드 잠금이 유지되는 동안 결과 만료와 이력 만료 모두 작업을 건너뛴다. 수동 기록 삭제도 동일 잠금 정책을 따른다.
- 이력은 현재 익명 서비스 전체에 표시된다. 원본 파일명/오류/메타데이터의 개인정보 가능성과 인증 부재를 고려해야 하며 공개 서비스의 사용자별 접근 통제는 아직 구현되지 않았다.
- 이력은 기존 목록 API를 이용한다. 대량 이력의 서버 페이지네이션/검색 성능은 이 검증 범위가 아니다.

## 검증

- Python 132개 테스트: 이력 유지·재시작 복구·기록 삭제·90일 만료·24시간 결과 보장·다운로드 보호·실패 재시도·업로드 만료·유효하지 않은 기간 거부.
- 웹 테스트 4개와 TypeScript/Vite 빌드 통과.
- `python scripts/history-fixture.py`로 별도 저장소의 완료/실패/취소/대기 스냅샷을 생성하고 실제 GC를 실행했다. 이는 상태·보관 테스트이며 실제 미디어/AI 작업이 아니다.
- Fixture: `data/history-fixtures/3b85f818512842a095371e7066c4dbff/report.json` (Git 제외).
- 데스크톱 `작업 이력` 탭에서 종료 작업 3개만 표시, 대기 작업 제외, 만료 완료 작업의 모든 다운로드 링크 숨김 확인.
- 만료 작업 `3060ade8551440cd9f13751abb2cf8cf`의 결과 요청 HTTP 410 확인. 브라우저 삭제 대화상자에서 기록 삭제 후 API 404와 작업 폴더 제거 확인.
- 완료 시간을 과거로 지정한 검증이며 실제 90일 경과 운영이나 모바일 UI 검증은 아니다. 기존에 TTL로 삭제된 이력은 복구하지 않는다.
