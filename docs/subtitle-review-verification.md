# 자막 편집 검증

2026-09-11.

## 흐름

1. 업로드 전에 `자막 검토 후 출력`을 선택한다. 기본 자동 처리 요청은 바뀌지 않는다.
2. Worker가 전사·번역과 원본 시간 복원을 끝내면 AWAITING_REVIEW 상태와 버전 1 초안을 저장하고 실행/인코딩 잠금을 놓는다.
3. 웹에서 언어 트랙 선택, 시작·종료 초, 문구 수정, 마지막 행 추가, 행 삭제, 초안 저장을 할 수 있다. 화면은 30 cue 단위로 나눈다.
4. 최종 출력 승인은 초안 저장 후 QUEUED로 바꾼다. 원본을 다시 분석하고 검토한 자막으로 인코딩하며 Gemini를 다시 호출하지 않는다.
5. 검증 성공 후 기존 규칙대로 원본과 work를 정리한다. 검토를 승인하지 않으면 기본 24시간 뒤 취소·정리한다.

초안은 `work/subtitle-draft.json`에 원자적 파일 교체로 저장한다. 버전 불일치는 409이며 다른 창의 수정을 덮어쓰지 않는다. 저장 후 승인 상태 기록 전에 장애가 나면 새 초안을 재조회해 승인할 수 있다. 별도 트랜잭션 DB를 사용하는 원자적 다중 파일 커밋은 아니다.

초안은 UTF-8/LF로 직렬화한 실제 바이트 수를 쓰기 전에 검사한다. 기존 초안과 새 임시 파일이 함께 존재하는 최대 순간을 고려해 새 파일 전체 크기를 추가 용량으로 계산한다. API와 Worker의 초안 생성은 접수 잠금을 공유한다. 검사에서 용량/여유 공간 부족 또는 실제 쓰기 중 디스크 가득 참이 감지되면 API는 507을 반환하고 승인하지 않는다. 이전 초안/버전은 유지하며 실패한 임시 파일은 가능한 경우 삭제한다. 다른 프로세스의 검사 직후 디스크 증가까지 막는 하드 할당량은 아니다.

초안 저장은 원래 시간 범위·중첩·비어 있지 않은 문구를 검증하고 기존 언어별 읽기 레이아웃으로 긴 문구를 분할한다. 단어별 정밀 시간 재정렬은 수행하지 않는다. 이미 완료된 결과를 편집하거나 기존 번인을 제거하는 기능은 아니다.

## 자동 검증

- Python 149개 테스트, 웹 4개 테스트, TypeScript/Vite 빌드 통과.
- 초안 조회/수정/승인, 오래된 버전 거부, 잘못된 트랙/시간/빈 문구/세 줄/밀리초 정밀도 거부, 긴 수정 문구 분할.
- 검토 대기 중 파일 보존, 검토 만료/취소 후 정리, 실행 잠금 충돌, 완료 후 편집 차단.
- Worker 준비 후 인코딩 미실행, 승인 후 전사/번역/추출 호출 횟수 증가 없이 수정 문구 출력.

후속 저장소 보호 회귀 포함 Python 156개 통과: UTF-8 정확한 크기, 기존 파일과 임시 파일 동시 용량, 접수 잠금 경합, 용량 거부 시 초안/버전/상태 유지, 부분 쓰기 및 파일 교체 실패 시 이전 JSON 보존과 임시 파일 정리. 실제 디스크를 가득 채우는 대신 별도 테스트 저장소의 제한값과 모의 OS 오류로 검증했다.
