# 개발 중 파일 보존

사용자가 개발 완료를 명시할 때까지 현재 사용자 저장소 `data/user-preview/jobs`와
기본 저장소 `data/video-jobs`에 `.preserve-artifacts` 표식을 유지한다.
이 표식은 로컬 데이터이며 Git에는 포함하지 않는다. 서버 재시작과 무관하게 유지된다.

- 성공, 실패, 취소 시 원본, 추출/전처리 음성, 자막, 출력 영상, 로그를 삭제하지 않는다.
- 결과/이력/업로드/검토 TTL 정리와 고아 디렉터리 정리를 건너뛴다.
- API 작업 삭제는 409로 거부한다. 저장소 직접 삭제 메서드도 거부한다.
- 중단된 작업의 실패 상태 복구는 계속 수행하지만 파일은 보존한다.
- 디스크 용량 제한과 업로드 무결성을 위한 미완료 청크 롤백은 그대로 유지한다.
- 이미 삭제된 파일을 복원하거나 아직 생성되지 않은 자막을 만드는 설정은 아니다.

## LLM 요청 및 원응답

보존 설정이 켜진 작업은 `work/llm/<UTC시각-고유ID>/`에 각 API 호출을 기록한다.
`request.json`에는 모델, 시도 번호, 프롬프트와 생성 설정을 포함한 요청 본문을 저장한다.
전사는 전처리 음성 기준 시작/끝 시간과 분할 깊이도 기록한다. 요청 본문의
인라인 음성(base64)도 포함하므로 실제 전송 구간을 다시 확인할 수 있다.
`response.json`에는 HTTP 상태와 파싱 전 응답 본문을 저장한다. 시간정보 검증 실패,
차단 응답, HTTP 오류도 기록하며, 네트워크 오류는 오류 클래스만 남긴다.
전사, 번역, 선택적 음성 필터 모두 같은 기록 경로를 사용한다.

API 키와 인증 헤더는 저장하지 않는다. 모델이 키를 반사한 경우에도 치환한다.
요청만 있고 응답이 없는 기록은 프로세스 중단 등으로 미완료된 호출일 수 있다.
기록에는 비공개 음성과 발화 내용이 포함될 수 있으므로 외부 공유/Git 추가를 금지한다.
기록은 디스크 용량 검사 대상이며 추가 공간을 소비한다. 과거에 저장하지 않은
모델 원응답은 소급 복구할 수 없다.

## 공식 Gemini SDK

LLM 호출은 `google-genai==2.23.0`의 비동기 `client.models.generate_content`를 사용한다.
전사 `gemini-3.5-transcribe`, 번역 `gemini-3.8-flash` 설정은 유지한다.
SDK에 HTTPX 전송 클라이언트를 제공하여 응답 훅에서 파싱 전 본문을 보존한다.
`response.json`의 `sent_request_body`는 SDK가 실제 직렬화해 전송한 본문이다.
SDK 내부 재시도는 1회로 제한하고 기존 워커의 제한된 재시도/취소/분할 정책을 적용한다.
공식 SDK가 모델의 잘못된 시간정보 자체를 수정하는 것은 아니다.
단위 테스트는 공식 SDK를 실제로 실행하되 HTTPX MockTransport로 외부 통신을 차단한다.

개발 완료 이후에도 표식을 임의로 제거하지 않는다. 제거 후에는 기존 TTL에 따라
오래된 파일이 즉시 삭제될 수 있으므로 사용자와 보존/정리 범위를 먼저 확인한다.
