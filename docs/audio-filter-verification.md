# 오디오 필터 설정 검증

2026-09-11.

## 현재 범위

| 설정 | 무음 정리 | 전사 후 태그 정리 |
| --- | --- | --- |
| off | 하지 않음, 전체 PCM 복사/항등 시간 매핑 | 빈 전사만 제외 |
| conservative | -45dB 이하 10초 이상, 양쪽 0.2초 여유 | 명시적 독립 비언어 태그 제외 |
| strong | -45dB 이하 5초 이상, 양쪽 0.2초 여유 | conservative와 같음 |

- 기본값은 기존 동작인 conservative다. UI는 각 무음 길이를 옵션 이름에 표시한다.
- strong도 소리 크기만으로 호흡/기합을 판정하지 않으며 "어", "아", "음", "핫" 같은 일반 텍스트를 삭제하지 않는다. 태그로 명시된 `[breath]` 등의 기존 정리만 적용한다.
- 원본 영상/오디오는 잘라내지 않는다. 전처리는 STT 입력만 줄이고 생성 자막은 원본 시간으로 복원한다.
- 필터 끄기는 실제 빈 자막을 생성하는 기능이 아니다. 빈 전사는 모든 모드에서 제외한다.
- 호흡·기합을 오디오에서 판별하는 모델과 실제 의미 보존 검증은 미구현이다. 이 변경으로 원래 요구사항의 이중 비언어 필터링이 완료되지는 않는다.

## 검증 결과

- Python 142개 테스트, 웹 4개 테스트와 빌드 통과. 옵션 검증/영속화/생성 충돌, off 전체 샘플 보존, 6초 무음의 강도별 처리, 원본 시간 복원, 일반 감탄사 보존 포함.
- 실제 FFmpeg 검사: 기존 합성 영어 음성 앞뒤에 0.3초 테스트 톤을 붙이고 6초·12초 무음 사이에 세 번 배치했다. 입력 41.305초에서 off 41.305초, conservative 29.705초, strong 24.105초를 얻었다.
- 제거된 구간이 모두 0 샘플인지, 유지 구간의 PCM이 원본과 byte 단위로 일치하는지, 시간 매핑에 따른 연결이 맞는지 검사했다. 톤으로 경계를 보호한 통제 입력이며 잡음 속 작은 목소리·속삭임·자연스러운 호흡 구간까지 보존을 입증하지는 않는다.
- PCM 보고서: `data/audio-filter-validation/9619f574456c463c9a0bbafd317fb279/report.json`.
- 같은 음성의 실제 Gemini 전사/한국어 번역 및 HEVC NVENC strong 작업 `fb9f794744a743a2bde5c8473e27ca4a` COMPLETED. 원문·번역 자막 9개, 반복 발화 시작 약 0.500/14.268/34.037초로 원본 위치 복원 확인. 최종 MP4 전체 디코딩 통과.
- Worker 보고서: `data/live-smoke/75e7323655174c849b25c4e8a4829e9f/report.json`. 생성된 테스트 영상은 약 43.167초이며 위 PCM 입력 길이와 구분한다.
- 데스크톱 필터 선택/배치 확인. 브라우저 실제 업로드 재개 시 옵션 복원과 모바일 화면은 이번 단계에서 별도 검증하지 않았다.

## 재현

```powershell
python scripts/smoke-audio-filter.py --audio data/stt-smoke.wav
python scripts/smoke-media.py --run-live --audio <fixture.wav> --audio-filter strong
```

첫 명령은 로컬 FFmpeg만 사용하고, 두 번째는 실제 Gemini 호출을 포함한다. 결과/입력/보고서는 Git 제외 경로에 저장한다.
